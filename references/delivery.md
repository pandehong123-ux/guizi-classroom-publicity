# 方案、确认状态与正式交付格式

所有命令中的 Skill/任务目录用实际绝对路径。内部清单和状态用于防止图文错配，不出现在公众号正文。脚本只验证结构、映射和确认摘要；语义与事实由独立审核角色核实。

## 方案阶段

`制作方案.md` 应包含本次入口、真实课堂内容、顺序、主题/标题方向、第一部分各预告项、第二部分各关卡的体验方向、每关两图的画面安排、特色活动、图片总数和待确认事项。没有缺项时注明“无待确认事实”。结尾明确当前版本待用户确认。

`图片清单.json` 格式如下（例子为单关结构，实际按完整课程填写）：

```json
{
  "version": 1,
  "sections": [
    {"id": "opening", "kind": "intro", "title": "课堂总体预告"},
    {"id": "gate-01", "kind": "gate", "title": "距离猜猜看"},
    {"id": "robot", "kind": "feature", "title": "机器人展示"}
  ],
  "images": [
    {"id": "01", "file": "images/01-opening.png", "section": "opening", "concept": "本次课堂亮点总览", "source": "用户活动说明与课件第2页"},
    {"id": "02", "file": "images/02-distance-a.png", "section": "gate-01", "concept": "学生先观察目标并猜测远近", "source": "实际互动入口和对应操作函数"},
    {"id": "03", "file": "images/03-distance-b.png", "section": "gate-01", "concept": "对照猜测与界面测距结果", "source": "实际读数更新逻辑"},
    {"id": "04", "file": "images/04-robot.png", "section": "robot", "concept": "机器人展示的活动示意", "source": "用户确认的线下活动说明"}
  ]
}
```

`kind` 仅为 `intro`、`gate`、`feature`。独立关卡必须为 `gate`，不要改成 feature 绕过两图要求。所有编号和相对文件唯一；文件为 `images/名字.png`。编号不按关卡重置，两份正文使用同一份清单。

正文 alt 以精确“图片01：”编号开头。文件名含空格时使用 `![图片01：说明](<images/01 观察.png>)`；平衡括号、转义和百分编码路径均可，最终解码路径须与清单一致。正文与提示词直接写成 Markdown 文件，不把整份文件包进代码围栏；代码示例内的图片或提示块不算正式内容。

```text
node <Skill>/scripts/workflow.mjs check <任务目录> --phase plan
```

方案检查成功仅表示结构有效。主控保存 `workflow-state.json` 为 `awaiting_confirmation`，然后把审核后的方案展示给用户并结束阶段。

## 用户确认与恢复

用户明确确认当前展示版本后，主控才能执行：

```text
node <Skill>/scripts/workflow.mjs approve <任务目录> --confirmation "用户确认当前方案的实际原话"
```

记录对 `制作方案.md` 与 `图片清单.json` 的 SHA-256 摘要、用户原话和时间。**不能为了通过工具而自行编造确认原话**。脚本不验证人类身份，用户确认来自对话记录，主控负责核对。测试工作目录中的模拟确认不能移用到真实项目。

恢复任务时读状态和最新用户消息；重新算摘要，文件变化时旧确认失效。未经确认时保留方案状态，不产生两份最终Markdown。制作中改变活动、顺序、数量或画面方向时更新方案并重新确认。正常润色/修错不改确认方案。

## 正式稿

`推广推文.md`：一个正式标题，开篇亮点图文交替，关卡及特色活动。图片位置例：

```markdown
## 第一关｜距离猜猜看

先猜猜目标有多远，
把你的判断交给测距来验证！

![图片02：观察目标并预测距离](images/02-distance-a.png)

启动测距，看看屏幕上的结果，
你的猜测和它相差多少？

![图片03：比较猜测与测距结果](images/03-distance-b.png)
```

只有真实实现提供这些操作时才采用此例的句子。

`推文配图生图提示词.md`：每个图片位置一个块，以唯一机器标记 `<!-- image:02 -->` 开始；按正文顺序排列。示例格式：

```markdown
<!-- image:02 -->
## 图片02｜第一关 · 观察与预测

文件：images/02-distance-a.png
位置：第一关第一张图
对应文案：先猜猜目标有多远，把你的判断交给测距来验证！
HTML依据：实际入口、页码/函数及操作内容
用途与画面：说明本图如何展示具体体验
素材身份：生成示意图，或优先实际截图/实拍与替代示意
比例：16:9
提示词：本张完整可复制提示词，包含主体、真实动作、画面反馈、场景、构图、色彩和风格。
约束：不增加课堂不存在的功能，不生成报名二维码；补充本张必要约束。
```

每块必须且仅有一条行首 `文件：` 字段，精确等于清单路径；旧路径备注不能替代文件字段。“对应文案”必须引用最终正文中连续的原句，可以将换行合并为一句。参考例子的字段内容运行时需填写真实文本；不得只写“与上一张相同”。完整提示词要含本张视觉细节，不得只复用一段总提示词。

在有有效确认后创建真实可见的示意占位图：

```text
node <Skill>/scripts/workflow.mjs placeholders <任务目录>
node <Skill>/scripts/workflow.mjs check <任务目录> --phase final
```

占位工具仅复制附带 PNG 到清单中尚不存在的路径，不覆盖用户后来替换的图片。Markdown alt 区分每个位置，示意图明确显示“配图位置 / IMAGE PLACEHOLDER”。正式AI生图另行由用户执行，或按用户新指令调用生图工具。

最终核心文件仅两份 Markdown；内部可保留分析、方案、清单、状态、反馈、审核记录。用户交付消息只需文件链接、图数、审核结论与实际未解决事项。
